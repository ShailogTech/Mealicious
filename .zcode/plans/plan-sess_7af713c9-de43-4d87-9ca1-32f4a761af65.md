## Group B — Tax/GST display (schema + pricing + UI)

### Schema
- Add `gstPct Float @default(0)` to `Product` (per-product slab). No change to `Order`/`OrderItem` (existing prices are GST-inclusive; we compute the breakdown at display time from the inclusive price + slab).
- `db:push` (non-destructive).

### #5 GST-inclusive pricing everywhere
- Storefront price components (`ProductCard`, `ProductDetail`, `ShopPage`, `HomePage`) already show `price`/`salePrice`. Append a small **"(incl. of all taxes)"** label under prices. No arithmetic change.

### #4 Tax slab on listing + CGST/SGST in cart & invoice
- **Listing:** `ProductCard`/`ShopPage` — show "GST: {gstPct}%" badge (only if `gstPct > 0`).
- **Cart/Checkout:** extend `src/lib/pricing.ts` `Totals` to compute `gstBreakdown` per line from the inclusive unit price:
  - `taxable = round(unit / (1 + gstPct/100))`
  - `gstAmount = unit - taxable`
  - `cgst = sgst = gstAmount / 2`
  - Aggregate per-line into totals `gstTotal`, `cgst`, `sgst`.
- **CartSidebar + CheckoutPage summary:** render a breakdown row "CGST ₹X · SGST ₹Y (inclusive)".
- **Invoice PDF:** the ERP's `invoice-pdf.ts` already shows CGST/SGST — extend `computeInvoice` (invoice-math.ts) to accept inclusive prices and split accordingly (currently treats price as pre-tax; small adjustment to the `taxable` formula). Invoice line items will carry `gstPct` from the product.

### #3 Admin-managed discounts (Prepaid + coupons)
- **New model:** `Discount` (id, code, type `prepaid|percent|flat`, value, minOrder, maxDiscount, isActive, appliesTo `online|cod|all`, createdAt). Replaces the hardcoded `COUPON_CODES` in pricing.ts and the hardcoded `0.10` prepaid logic.
- **Seed:** migrate the existing 5 coupons + the 10% prepaid rule into `Discount` rows (idempotent upserts).
- **Admin UI:** new `/admin/discounts` page (CRUD via `ErpDataTable`/`ErpFormDrawer` — established pattern) + API `/api/admin/discounts`. Toggle isActive, edit value/minOrder.
- **pricing.ts:** `computeTotals` reads active discounts from DB (prepaid discount now driven by a `type:'prepaid'` row; coupons by `type:'percent'|'flat'` rows). Keep the in-memory fallback for safety.

## Group C — ERP enhancements

### #7 Per-employee access override checklist

- **Registry:** add `documents` module key + icon.

### #9 WhatsApp button after invoice creation
- **Helper:** new `src/lib/administrator/whatsapp-share.ts` — `buildInvoiceWaLink(mobile, invoiceNumber, grandTotal)` → `https://wa.me/<normalized>?text=<encoded "Invoice INV-X for ₹Y...">`. Client-side (wa.me scheme, not the Cloud API).
- **Billing:** `BillingClient.tsx` — on success, capture the returned `invoice` (currently discarded), show a "Send via WhatsApp" button alongside the existing redirect. Opens wa.me in a new tab.

### #6 Admin↔ERP inventory sync + order→ERP invoice
- **Inventory link:** add `erpInventoryItemId String? @unique` to `Product` (optional 1:1 to `ErpInventoryItem` by SKU). Admin Products page gets a "Link to ERP item" select; when linked, stock changes propagate both ways via a small `syncInventory(productId)` helper (transactional update of both tables).
- **Order→ERP invoice:** on store order creation (`/api/orders/route.ts` POST), after the order is committed, call a new `createErpInvoiceFromOrder(orderId)` helper that:
  - Resolves customer by phone (`ErpCustomer.mobile` upsert — phone is the join key, confirmed viable).
  - Maps `OrderItem` → ERP line `{name, qty, price (inclusive), disc:0, gstPct: product.gstPct}`.
  - Calls the existing `computeInvoice` + creates `ErpInvoice` + `ErpTransaction` (Income) — reuses the billing POST logic, factored into a shared helper.
  - Stores `erpInvoiceNumber` on the Order (new optional column) for traceability.
- **Manual trigger:** also add a "Sync to ERP" button on the admin Orders page for retroactive sync of older orders.
- **Bidirectional guard:** sync is idempotent (skip if `erpInvoiceNumber` already set).
